## 2. 확정한 제품 결정

### 2.1 Primary Persona

- 설비·생산 매니저
- 설비·공정 엔지니어

모델 개발자·데이터 분석가는 최종 사용자가 아니라 검증 담당 Secondary Persona로 분리한다.

### 2.2 역할별 핵심 차이

| 구분 | 매니저 | 엔지니어 |
|---|---|---|
| 첫 질문 | 어떤 설비에 어떤 결정을 내려야 하는가? | 어떤 센서가 왜 비정상적인가? |
| 첫 정보 | 위험도·영향·권장 결정 | 센서 변화·이상 구간·주요 근거 |
| 주요 행동 | 판단·점검 요청·담당자 지정 | 분석·점검·기록·보고 |
| 모델 상세 | 기본 숨김 | 필요 시 열람 |
| 차트 | 필요할 때 확장 | 기본 노출 |

### 2.3 지원 결정

- `continue_monitoring`
- `request_inspection`
- `review_shutdown`
- `hold_for_data_check`

실제 설비 제어와 자동 작업 지시 실행은 범위에서 제외한다.

### 2.4 동적 UI 경계

LLM 또는 Planner가 임의 React 코드·HTML·JavaScript를 생성하지 않는다. 등록된 UI 블록 중 필요한 블록과 순서만 선택한다.

## 3. Gold 시나리오

| ID | 사건 | 기대 핵심 동작 |
|---|---|---|
| GS-001 | 정상 설비 | 불필요한 경고·점검·정지 권고를 만들지 않음 |
| GS-002 | 공구 마모 위험 | 공구 마모와 토크 상호작용을 근거로 점검 요청 |
| GS-003 | 열 방출 이상 | 공정·공기 온도 차이를 근거로 냉각 계통 점검 |
| GS-004 | 동력·토크 과부하 | 높은 우선순위와 사람의 정지 검토 요청 |
| GS-005 | 복합 이상 | 여러 근거를 나열하지 않고 주·보조 요인으로 순위화 |
| GS-006 | 저신뢰 결과 | 확정 고장 대신 불확실성과 추가 확인 안내 |
| GS-007 | 데이터 품질 문제 | 추론을 보류하고 데이터 확인을 우선 |
| GS-008 | LLM·Planner 장애 | 규칙 기반 리포트와 기본 레이아웃으로 계속 동작 |

## 4. 안전 기준

모든 단계에서 다음 규칙을 지켜야 한다.

- 예측 고장 유형을 확정된 근본 원인으로 표현하지 않는다.
- 저신뢰 결과를 확정 고장으로 표현하지 않는다.
- 데이터 품질 문제가 있으면 정상·고장 판단을 보류한다.
- 실제 설비 제어가 수행됐다고 표현하지 않는다.
- 실제 작업 지시가 자동 승인됐다고 표현하지 않는다.
- 모든 수치 문장은 Evidence Package에 추적 가능해야 한다.
- 매니저와 엔지니어 화면의 원본 사실이 서로 모순되면 안 된다.

## 5. 검증 결과

### YAML 구조 검증

`evaluation/gold_scenarios.yml`을 Python `yaml.safe_load`로 로드했다.

```text
YAML_OK
suite_id= factory-signal-board-mvp-gold-v1
scenario_count= 8
scenario_ids= GS-001,GS-002,GS-003,GS-004,GS-005,GS-006,GS-007,GS-008
roles= manager,engineer
```

### 완료 조건 확인

- [x] 8개 Gold 시나리오가 정의됐다.
- [x] 각 시나리오에 미래 fixture 경로가 지정됐다.
- [x] 기대 위험 상태와 추천 결정이 정의됐다.
- [x] 필요한 주요 근거와 금지 단정이 정의됐다.
- [x] 매니저·엔지니어별 필수 UI 블록과 행동이 정의됐다.
- [x] 저신뢰·데이터 품질·LLM 장애 시나리오가 포함됐다.
- [x] 역할 간 수치·근거 일관성 규칙이 정의됐다.

## 6. 아직 수치로 확정하지 않은 항목

다음 내용은 고의로 1단계에서 확정하지 않았다.

- 센서별 정상 범위와 물리 단위: 2단계 데이터 사전에서 확정
- Gold fixture의 실제 센서 값: 2단계에서 생성
- 모델 구조와 성능 수치: 3단계에서 확정
- `normal`, `attention`, `warning`, `critical` 확률 경계: 4단계에서 확정
- 개별 변수의 기여도 계산 방식: 5단계에서 확정
- LLM Provider와 최종 프롬프트: 7단계에서 확정

이는 요구사항이 구현 결과를 미리 조작하지 않도록 하기 위한 단계 분리다.

## 7. 2단계 진입 조건

2단계에서는 다음 순서로 진행한다.

1. AI4I 2020 데이터 출처와 컬럼을 검증한다.
2. 학습 입력 피처와 사후 분석용 고장 모드 컬럼을 분리한다.
3. 데이터 누수 검사를 자동화한다.
4. 센서 단위와 파생변수 정의를 문서화한다.
5. GS-001부터 GS-008까지 작은 JSON fixture를 생성한다.
6. 모든 fixture를 공통 입력 스키마로 검증한다.

## 8. Git 상태 주의사항

현재 `mvp-프로젝트2`는 상위 경로의 Git 저장소에 포함되어 있고 독립 `.git` 디렉터리가 아직 없다. 상위 저장소에 프로젝트 파일을 잘못 커밋하지 않도록, 다음 단계의 커밋 전에 `scripts/bootstrap_git.sh`로 독립 저장소를 초기화해야 한다.
