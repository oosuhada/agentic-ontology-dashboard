최종 생성 데이터셋

canonical-ai4i-physics-v3.1은 Azure PdM의 다설비·시계열 패턴과 AI4I의 물리 변수 관계·고장 조건을 참고해 생성한 검증된 합성 데이터셋입니다.

  • 압축기 20대와 CNC 80대를 명시했습니다.
  • 사업장 4개 → 셀 20개 → 자산 100대의 계층을 만들었습니다.
  • 압축기와 CNC 사이 공기 공급 관계 80건을 정의했습니다.
  • 정비 유형, 원인 사건 식별자와 공구 교체 여부를 데이터 필드로 제공했습니다.
03 · CHANGE HISTORY

세 차례 변경 과정

7월 30일

AI4I 2020 → CiP-DMD

AI4I의 각 행은 독립 제품 표본이며 어느 설비에서 가공되었는지와 시간 순서가 정의되지 않았습니다. 동일 설비의 상태 변화, 설비 간 상대 비교와 우선순위 목록을 만들 수 없어 CiP-DMD로 전환했습니다.

이 단계에서 필드 단위 신뢰 출처를 지정하고, 누락값 처리를 임의 대체가 아닌 출처 대조로 규정했습니다.

8월 1일

CiP-DMD → Azure Predictive Maintenance

CiP-DMD의 설비는 3대뿐이어서 관리자 우선순위 화면이 단순 나열에 그쳤습니다. Azure PdM은 설비 100대, 고장 761건, 오류 3,919건과 정비 3,286건을 제공해 비교 관점을 확장할 수 있었습니다.

부품별 고장 전 센서 편차와 오류 후 고장 전환율을 확인했으며, 연식 교란을 확인한 뒤 관측 데이터에서 인과를 주장하지 않는 원칙을 세웠습니다.

8월 5일

Azure PdM → canonical-ai4i-physics-v3.1

Azure PdM은 설비 수는 충분했지만 설비 종류, comp1~4의 물리적 정체, error1~5의 의미와 압력·진동 단위를 정의하지 않았습니다. “comp3에 연관된 센서가 높습니다”는 쓸 수 있었지만 “가압 계통을 점검하십시오”는 쓸 수 없었습니다.

데이터에 없는 정보를 역추정하는 구조가 실제 경계 조건 결함으로 이어져, 외부 데이터셋 탐색을 중단하고 요구사항에 맞춘 데이터셋을 직접 생성했습니다.

08 · LIMITATIONS

남아 있는 제약도 함께 공개했습니다

현재 제약

  • 합성 데이터: 생성 규칙이 공개되고 검증되었지만 실제 공장 계측값은 아닙니다.
  • 인과 주장 불가: 자산 관계가 존재해도 인과로 단정하지 않습니다.
  • 관계 미학습: 자산 관계를 현재 모델 학습에는 사용하지 않았습니다.
  • 등급 변별력: 관찰 등급의 변별력이 확인되지 않았습니다.
