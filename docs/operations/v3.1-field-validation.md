# Canonical V3.1 필드 검증표

## 검증 기준

- Dataset: `canonical-ai4i-physics-v3.1`
- Model: `independent-logreg-v3.1`
- Result Artifact: `result-artifact-v1.0`
- 검증일: 2026-08-07

## 패키지 결과

| 항목 | 결과 |
|---|---|
| Canonical 원천 파일 6개 SHA-256 | 전부 manifest와 일치 |
| Evaluation truth 3개 SHA-256 | 전부 manifest와 일치 |
| 모델 출력 5개 SHA-256 | 전부 model contract와 일치 |
| Package validation | `valid: true` |
| Reproducibility validation | `valid: true` |
| Result Artifact | 100행, 자산 100대와 1:1, 오류·중복·미등록 자산 0건 |

검증한 ZIP의 SHA-256은
`7f60ff5e8e921d66e009441877c02c61eb0ad1ba18a4a10ffc871b4b9731f7c6`이다.
공식 `.zip.sha256`이 별도로 제공되지 않아 외부 배포본과의 진위 비교만 미완료다.

## Result Artifact 변경표

기존 샘플은 `canonical-independent-v1.1`과 `independent-logreg-v1.3`을
참조하므로 V3.1 샘플로 이관하지 않는다.

| 기존 계약 | V3.1 계약 | 판정 |
|---|---|---|
| 없음 | `artifact_id` | 신규 |
| 없음 | `artifact_type=predictive_maintenance_result` | 신규 |
| `schema_version` | `schema_version` | 동일 |
| top-level `prediction_id` | `provenance.prediction_id` | 위치 변경 |
| `asset_id`, `asset_type`, `observed_at` | 동일 | 동일 |
| `prediction_horizon_hours` | 동일 | 동일 |
| 없음 | `prediction_task=binary_failure_within_horizon` | 신규 |
| `failure_probability`, `status_grade`, `confidence` | 동일 | 동일 |
| `predicted_failure_type` | 동일 필드 | 의미 수정: 고장 모드가 아닌 binary 위험 class |
| 최대 5개 factor | 정확히 Top-3 | 계약 변경 |
| `contribution` | `signed_contribution` | 이름·의미 변경 |
| 없음 | `feature_value`, `explanation_method` | 신규 |
| `action_code` | `action` | 이름 변경 |
| `recommended_action.message` | 없음 | Artifact에서 삭제, 표시/LLM 계층에서 생성 |
| top-level `model_version` | `provenance.model_version` | 위치 변경 |
| top-level `dataset_version` | `provenance.dataset_version` | 위치 변경 |
| 없음 | `provenance.source_type` | 신규 |
| 없음 | `provenance.canonical_source_mutated=false` | 신규 |

## 파생·저장 필드 처리

| 필드/정보 | 분류 | Operations 처리 |
|---|---|---|
| `site_id`, `cell_id`를 Artifact 응답에 포함 | API 결합 | `asset_master`에서 결합했다고 명시 |
| 위험 등급별 설비 수 | API 계산 | 같은 기준시각의 최신 Artifact 집계 |
| 가동 설비 수 | API 계산 | 자산별 최신 observation 집계 |
| `top_reason` | ViewModel 계산 | `top_factors[0]`에서 파생 |
| 권고 한국어 문장 | 표시/LLM 파생 | action enum과 분리해 관리 |
| `risk_status` | API 결합 | 생산 작업의 CNC와 최신 Artifact 결합 |
| `display_name` | 애플리케이션 저장 | 정책 합의 전 `asset_id` 사용 |
| Decision, Note | 애플리케이션 저장 | Operations 포함 여부 합의 필요 |
| 정비 요청·알림·권한 | 애플리케이션 저장 | 멘토링 기준상 Operations 이후 |

## 이관 원칙

- 원천 센서와 파생 예측을 분리한다.
- evaluation truth를 제품 화면과 일반 API에 노출하지 않는다.
- topology를 고장 인과관계로 단정하지 않는다.
- 예측 확률과 권고를 실제 고장 또는 자동 실행 명령으로 표현하지 않는다.
- 화면, API, LLM은 같은 Result Artifact 계약을 사용한다.
