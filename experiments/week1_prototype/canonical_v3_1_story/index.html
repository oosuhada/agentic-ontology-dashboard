최종 생성 데이터셋

canonical-ai4i-physics-v3.1은 Azure PdM의 다설비·시계열 패턴과 AI4I의 물리 변수 관계·고장 조건을 참고해 생성한 검증된 합성 데이터셋입니다.

  • 압축기 20대와 CNC 80대를 명시했습니다.
  • 사업장 4개 → 셀 20개 → 자산 100대의 계층을 만들었습니다.
  • 압축기와 CNC 사이 공기 공급 관계 80건을 정의했습니다.
  • 정비 유형, 원인 사건 식별자와 공구 교체 여부를 데이터 필드로 제공했습니다.
03 · CHANGE HISTORY

외부 데이터셋 선택부터
내부 Canonical 버전까지

7월 30일

AI4I 2020 → CiP-DMD

AI4I의 각 행은 독립 제품 표본이며 어느 설비에서 가공되었는지와 시간 순서가 정의되지 않았습니다. 동일 설비의 상태 변화, 설비 간 상대 비교와 우선순위 목록을 만들 수 없어 CiP-DMD로 전환했습니다.

이 단계에서 필드 단위 신뢰 출처를 지정하고, 누락값 처리를 임의 대체가 아닌 출처 대조로 규정했습니다.

8월 1일

CiP-DMD → Azure Predictive Maintenance

CiP-DMD의 설비는 3대뿐이어서 관리자 우선순위 화면이 단순 나열에 그쳤습니다. Azure PdM은 설비 100대, 고장 761건, 오류 3,919건과 정비 3,286건을 제공해 비교 관점을 확장할 수 있었습니다.

부품별 고장 전 센서 편차와 오류 후 고장 전환율을 확인했으며, 연식 교란을 확인한 뒤 관측 데이터에서 인과를 주장하지 않는 원칙을 세웠습니다.

8월 4일
11:44

Azure PdM 분석 → independent-baseline-v1.1

Azure PdM은 설비 수는 충분했지만 설비 종류, comp1~4의 물리적 정체, error1~5의 의미와 압력·진동 단위를 정의하지 않았습니다. “comp3에 연관된 센서가 높습니다”는 쓸 수 있었지만 “가압 계통을 점검하십시오”는 쓸 수 없었습니다.

외부 데이터셋 탐색을 멈추고 Azure 계열 압축기와 AI4I 계열 CNC를 독립 baseline으로 생성했습니다. 압축기–CNC 연결은 원본 센서에 합치지 않고 선택적 connected-air scenario overlay로만 분리했습니다.

구현 · 신성민, 장우수리뷰 · 유호범, 장우수초기 피드백 7개
8월 4일
12:17

자산 혼합 구조 → 명시적 Asset Topology

하나의 line에 압축기 센서와 CNC 센서를 섞던 구조를 폐기했습니다. 4개 사업장, 20개 셀, 압축기 20대와 CNC 80대를 별도 자산으로 만들고 SUPPLIES_AIR_TO 80건을 관계 데이터로 분리했습니다.

이 단계부터 “센서 관측값”과 “설비 구성 관계”를 같은 사실처럼 취급하지 않는 경계가 명확해졌습니다.

8월 4일
13:42

canonical-independent-v1.0

Canonical source, Evaluation truth, Derived model output, Optional agent experiment의 네 계층을 분리했습니다. 실패 정답과 합성 원인은 모델·에이전트가 읽지 못하도록 숨기고, manifest와 checksum으로 원천·정답·결과 파일을 결합했습니다.

이 버전에서 30일 데이터, 100개 자산, 432,000개 센서 관측과 독립 모델 sanity benchmark가 하나의 재현 가능한 패키지로 정리되었습니다.

8월 4일
14:30

Predictive Maintenance Canonical V2

검증된 canonical source를 유지하면서 68,211행 Prediction Timeline, Time Machine Replay, SSE event stream, seek·pause·resume과 cross-platform ZIP 배포를 추가했습니다.

새 센서를 즉석 생성하는 방식이 아니라 같은 canonical CSV를 시간순으로 재생하도록 고정해, 발표 화면과 검증 결과가 서로 다른 데이터를 보지 않도록 했습니다.

구현 · 장우수, 신성민리뷰 · 장우수, 고광우4차 검토 8개

17:42

AI4I Physics Upgrade

V2에서 거의 성립하지 않던 CNC 물리 관계를 수정했습니다. 공기온도–공정온도, 회전속도–토크 관계와 PWF·HDF·OSF·TWF·RNF 조건을 생성·검증 계약으로 만들고, local-only negative agent case와 Result Artifact를 추가했습니다.

이 시점의 작업 폴더 이름은 V3였지만 내부 dataset identity는 이미 canonical-ai4i-physics-v3.1이었습니다. 따라서 별도 V3.0 배포본으로 보지 않습니다.

Canonical V3.1 Release Candidate

팀 리뷰에서 발견된 공구 마모 초기화 경계 결함을 수정했습니다. Tool wear reset을 running 행이 아니라 정비 시작 tick에만 허용하고, 731개 공구 교체 이벤트와 731개 reset의 1:1 정렬을 release gate로 추가했습니다.

Agent evidence에 실제 maintenance ID·시작·완료 시각·tool_replaced 검증을 추가하고, RPM 생성식과 문서 설명도 실제 구현과 일치시켰습니다.

08 · LIMITATIONS

남아 있는 제약도 함께 공개했습니다

현재 제약

  • 합성 데이터: 생성 규칙이 공개되고 검증되었지만 실제 공장 계측값은 아닙니다.

  • 관계 미학습: 자산 관계를 현재 모델 학습에는 사용하지 않았습니다.
  • 등급 변별력: 관찰 등급의 변별력이 확인되지 않았습니다.
