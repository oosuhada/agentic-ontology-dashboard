# Factory Signal Board MVP Scope

## 1. 제품 정의

Factory Signal Board는 제조 설비의 센서 데이터와 예측·이상 탐지 결과를 근거 데이터와 함께 해석하고, 매니저와 엔지니어의 역할에 따라 필요한 설명·차트·조치 정보를 다르게 구성하는 의사결정 지원 MVP다.

이 프로젝트의 핵심은 고장 예측 정확도 경쟁이나 고정형 모니터링 화면이 아니다.

> 같은 설비 사건을 두고도 매니저에게는 판단과 우선순위를, 엔지니어에게는 기술 근거와 점검 항목을 제공한다.

## 2. 해결하려는 문제

현재 제조 현장의 분석 결과는 다음과 같은 단절을 가진다고 가정한다.

- 모델 점수와 실제 업무 판단 사이에 해석 계층이 없다.
- 매니저와 엔지니어가 같은 화면과 같은 설명을 받는다.
- 고정형 대시보드는 사용자의 현재 질문과 역할을 반영하지 못한다.
- LLM이 작성한 설명이 어떤 데이터에서 나왔는지 추적하기 어렵다.
- 모델 또는 LLM 장애 시 전체 서비스가 무용해질 수 있다.

MVP는 다음 질문에 답할 수 있어야 한다.

### 매니저 질문

- 지금 가장 먼저 봐야 할 설비는 무엇인가?
- 실제 조치가 필요한가?
- 생산 영향과 위험 수준은 어느 정도인가?
- 담당 엔지니어에게 무엇을 요청해야 하는가?

### 엔지니어 질문

- 어떤 센서가 언제부터 비정상적으로 변했는가?
- 위험도를 올린 주요 근거는 무엇인가?
- 예상 고장 유형은 무엇이며 무엇을 점검해야 하는가?
- 매니저에게 어떻게 보고해야 하는가?

## 3. MVP의 핵심 사용자

| 사용자 | 제품에서 해결할 핵심 과업 | 기본 화면 |
|---|---|---|
| 설비·생산 매니저 | 위험 설비 우선순위 확인, 조치 판단, 엔지니어에게 지시 | 결정 중심 요약 화면 |
| 설비·공정 엔지니어 | 이상 구간 확인, 근거 분석, 점검 수행, 매니저 보고 | 증거 중심 분석 화면 |

모델 개발자·데이터 분석가는 MVP의 최종 사용자가 아니다. 모델 실험과 검증 정보는 별도 관리자 또는 상세 영역으로 분리한다.

## 4. 지원하는 의사결정

MVP는 실제 설비를 자동 제어하지 않는다. 사용자가 다음 결정 중 하나를 선택하도록 돕는다.

- `continue_monitoring`: 계속 운전하며 모니터링
- `request_inspection`: 현장 점검 요청
- `review_shutdown`: 계획 정지 또는 즉시 정지 검토
- `hold_for_data_check`: 데이터 품질 확인 전 판단 보류

추천 결정은 Evidence Package와 운영 정책에서 계산되며, LLM은 계산된 결정을 임의로 바꾸지 않는다.

## 5. 핵심 수직 흐름

```text
AI4I·합성 설비 데이터
→ 데이터 검증과 피처 생성
→ 고장 확률·고장 유형 예측
→ 운영 임계값과 위험 등급
→ 개별 예측 근거
→ Evidence Package
→ 규칙 기반 리포트
→ 선택적 LLM 리포트
→ 역할·질문 의도 기반 UI Block Planner
→ React 역할별 대시보드
→ 사용자 판단·점검·메모 기록
```

## 6. 필수 범위

### 데이터·모델

- AI4I 2020 원본 데이터 로딩과 검증
- 데이터 누수 가능성이 있는 고장 유형 컬럼 분리
- 최소 1개 단순 베이스라인과 1개 비교 모델
- Precision, Recall, F1, Average Precision, 혼동행렬 기록
- 모델과 별도로 관리되는 운영 임계값 정책
- 개별 예측의 주요 근거 생성

### 설명·리포트

- 모델과 UI 사이의 공통 Evidence Package JSON 계약
- Evidence Package만 사용해 생성되는 규칙 기반 리포트
- 매니저용·엔지니어용 LLM 리포트
- 수치·근거·불확실성 추적 가능성
- LLM 장애 시 규칙 기반 fallback

### UI·업무 흐름

- React 기반 최종 사용자 UI
- 매니저·엔지니어 역할 전환 또는 역할별 진입
- 동일 사건에 대한 역할별 다른 블록 순서와 설명 깊이
- 허용된 UI 블록만 사용하는 동적 레이아웃
- 점검 요청, 판단, 메모 같은 사용자 행동 기록
- Gold 시나리오를 재현하는 데모 모드

### 품질

- API·스키마·UI 계약 테스트
- Gold 시나리오 자동 검증
- 한 명령으로 로컬 실행 가능한 구조
- 비밀정보와 실제 고객 데이터 미포함

## 7. 제외 범위

- 실제 설비 제어 및 자동 정지
- 실제 CMMS·MES·ERP 쓰기 연동
- 프로젝트 3 Knowledge Graph 전체 구현
- 완전 자유 형식 HTML·JavaScript 생성형 UI
- 다중 테넌트·정교한 인증·권한 관리
- 실시간 공장 스트리밍 인프라
- 최고 성능 모델 경쟁
- 3D 디지털 트윈
- 자동 작업 지시 실행
- 고객사별 완전한 커스터마이징

## 8. 선택 확장

다음 기능은 핵심 수직 흐름이 통과한 뒤 추가한다.

- 프로젝트 3 Neo4j Context Adapter
- LlamaIndex 기반 유지보수 매뉴얼 RAG
- WebSocket 센서 시뮬레이션
- 다중 설비 위험 우선순위화
- 작업 지시 승인 워크플로
- PDF 리포트 내보내기
- 내부 모델 검증용 Streamlit 콘솔

## 9. 허용된 UI 블록 카탈로그

MVP의 Planner는 아래 블록만 선택하고 순서를 정할 수 있다.

| 블록 | 목적 | 기본 사용자 |
|---|---|---|
| `StatusSummary` | 설비 상태와 핵심 결론 | 공통 |
| `RiskKpi` | 위험도·등급·임계값 | 공통 |
| `PriorityList` | 여러 설비의 우선순위 | 매니저 |
| `ImpactSummary` | 예상 생산 영향·정지 영향 | 매니저 |
| `ManagerDecisionCard` | 권장 결정과 승인·메모 | 매니저 |
| `SensorLineChart` | 센서 시계열과 이상 구간 | 엔지니어 |
| `AnomalyTimeline` | 이상 발생 시점과 이벤트 순서 | 엔지니어 |
| `FactorContribution` | 위험도를 올린 주요 변수 | 엔지니어 |
| `EvidenceTable` | 현재 값·기준 범위·기여 방향 | 엔지니어 |
| `RecommendedActions` | 권장 조치 목록 | 공통 |
| `EngineerChecklist` | 현장 점검 항목과 상태 | 엔지니어 |
| `DataQualityWarning` | 결측·범위 오류·저신뢰 경고 | 공통 |
| `ModelDetails` | 모델 버전·임계값·성능 상세 | 접힌 상세 영역 |

LLM은 React 코드나 임의 HTML을 생성하지 않는다.

## 10. 데모 기본 흐름

### 데모 A: 매니저

1. 위험 설비 목록을 연다.
2. 공구 마모 위험 설비를 선택한다.
3. 위험도, 예상 영향, 권장 결정을 확인한다.
4. 근거 요약을 펼쳐 본다.
5. `점검 요청`을 선택하고 엔지니어에게 전달할 메모를 남긴다.

### 데모 B: 엔지니어

1. 같은 설비 사건을 연다.
2. 공구 마모와 토크 변화 차트를 확인한다.
3. 주요 위험 기여 변수를 확인한다.
4. 점검 체크리스트를 수행한다.
5. 매니저 보고용 요약을 생성한다.

### 데모 C: 안전한 실패

1. 데이터 품질 문제가 있는 설비 사건을 연다.
2. 시스템이 고장이라고 단정하지 않고 판단 보류를 표시한다.
3. LLM을 비활성화한다.
4. 규칙 기반 리포트와 기본 화면이 계속 동작하는지 확인한다.

## 11. 완료 조건

1단계 이후 팀은 다음 문장을 구체적으로 설명할 수 있어야 한다.

- 누구를 위한 제품인가?
- 같은 사건에서 매니저와 엔지니어 화면은 무엇이 다른가?
- 어떤 결정을 지원하고 어떤 결정은 지원하지 않는가?
- 정상·고장·불확실성·데이터 오류를 어떻게 구분하는가?
- LLM이 실패해도 무엇이 남아 동작하는가?

MVP 최종 완료는 다음 기준으로 판단한다.

- 8개 Gold 시나리오가 모두 재현된다.
- 모든 리포트 수치가 Evidence Package와 일치한다.
- 역할별 필수 UI 블록과 행동이 다르게 제공된다.
- 데이터 품질 문제와 저신뢰 결과를 고장으로 단정하지 않는다.
- LLM 장애 시 규칙 기반 리포트와 화면이 정상 동작한다.
- 실제 설비 제어나 무승인 자동 조치를 수행하지 않는다.
